# Project Architecture Rules

- Keep Pipe assignment options separate from historical owner lists so visibility flags never remove legacy names from reports, dashboards, goals, rankings, or history.
- ContractTab is the shared contract form and generation entry point; the backend check chooses the document model and controls readiness, while report-only payment validation stays in reportContract with unit tests.
- Use DocumentoBadge for document classification in Kanban/detail headers and missingMeetingBasics for meeting-only validation so contract checks remain unchanged.
- Mount presence once in AuthLayout for an authenticated profile; keep geolocation collection separate from normal heartbeats so location never prompts on a regular ping.
- Mount version checks once in AuthLayout outside page data queries; version polling must not trigger Pipeline synchronization, and administrative reload signals use the existing RPC only after confirmation.- Campanhas de Disparo only reads campaign views/tables and toggles campanha_config; contact status priority lives in campanhaDisparo with unit tests, and the frontend never calls WhatsApp providers directly.
- Open lead cards from outside the Pipeline via /lead/:id (or /pipeline?lead=); PipelinePanel always fetches the lead by id so cards open regardless of the loaded list or active filters, and the shared LeadDrawer stays the only detail view.
- Meta Ads actions (overview, status, budget, video upload/status) go only through the meta-manager edge function; the frontend never reads meta_ads_config, and budget/registration rules live in metaCampanhas with unit tests.
- The Marketing "Reuniões realizadas" card counts leads by current post-meeting stage and stage-change month regardless of lost status, via useReunioesRealizadasMes, so it never depends on farol_metricas_sdr.
- Keep lunch/block controls within the shared attendance screen; read effective blocks from the existing RPC and select before inserting/updating lunch by id because its unique indexes are partial.
- Keep profile lookup/linking and deletion checks in userProfileAccess; authentication must never recreate a missing profile, so removing access survives the next login or profile refresh.
- Black Ops reads evaluation criteria/guardrails by rubric version separately from the active legend and batches factual seals by meeting IDs, so historical scores remain unchanged and rows never fetch seals individually.
- Mount weekly meeting queries only within their Black Ops tab and training queries only on the /treinamento page; use existing authenticated views/RPCs for access, signed private training URLs for one hour, and user-scoped progress mutations so other screens and users remain isolated.
- Key featured meetings by period and keep Read AI video URLs only in the mounted player with one refresh per playback failure, so monthly/weekly caches stay isolated and expiring URLs are never persisted.
- Training rows are built by trainingRows in seTraining from active tracks, approved contents and focus rows; focus only reorders/labels rows (admins pick a closer, sellers rely on backend visibility without identity filters), and cover resolution lives in trainingCover so cards and the admin form never diverge.
